Software Development Life Cycle

The systematic roadmap for building quality software

What is the SDLC?

A structured process for building software that ensures quality and efficiency. It reduces waste of time and resources, ensures the software meets user needs, and provides clear goals and management structure.

The 5 Major Phases

Analysis
Design
Dev
Testing
Maintenance
Analysis

Gathering requirements from stakeholders to understand what the software must do.

Design

Planning architecture, user interfaces, and data structures. The blueprint phase.

Development

The actual coding phase where programmers write and build the software.

Testing

Identifying bugs and ensuring everything works as specified before release.

Maintenance

Fixing issues and adding features after deployment. The longest phase.

SDLC Methodologies

Staged

Waterfall

A linear, sequential model where progress flows downwards like a waterfall. Each phase must be completed before the next begins.

  • Easy to manage due to rigidity
  • Best for fixed, clear requirements
  • High risk if changes needed late
Iterative

Iterative Model

Development begins with a small set of requirements and iteratively enhances the software through repeated cycles.

  • Early prototypes created quickly
  • Feedback informs next version
  • Reduces risk by finding issues early
Agile

Agile

An iterative approach focused on collaboration, customer feedback, and small frequent releases.

  • Works in "Sprints" (2-4 weeks)
  • Highly flexible and adapts to change
  • Delivers working software early

Model Comparison

Feature Staged (Waterfall) Iterative Agile
Flexibility Low (Fixed) Medium Very High
Customer Involvement Start & End only Periodic Continuous
Delivery Single (at the end) Multiple (versions) Small & Frequent
Best for... Stable Requirements Large Scale Projects Fast-changing Needs

Key Roles

Project Manager

The leader overseeing the entire lifecycle. Sets goals, manages timelines, allocates resources, and ensures communication.

Business Analyst

The bridge between client needs and the technical team. Gathers requirements and translates "what the user wants" into specs.

Developer

Writes the actual source code. Implements designs, solves algorithmic problems, builds frontend and backend systems.

Software Tester (QA)

Ensures the final product meets quality standards. Identifies bugs and verifies that requirements are met.

Stakeholders

Anyone with interest in the software: clients, end users, investors. Provide feedback and approve the final product.

Real-World Application

Banking System (Waterfall)

Regulations are strict and security is paramount. Requirements rarely change mid-project. A structured, step-by-step approach ensures compliance.

Social Media App (Agile)

User preferences change daily. Apps like Instagram or TikTok use Agile to release weekly updates, testing new features with real users.

Testing & Quality Assurance

Evaluating, debugging, and refining digital solutions

Why Testing is Critical
Reliability
Ensures software performs consistently under expected conditions.
Safety & Security
Prevents catastrophic failures in safety-critical systems.
Cost Efficiency
Fixing bugs early is significantly cheaper than post-release.
User Experience
Protects brand reputation by delivering smooth, bug-free products.
Testing vs. Debugging

Testing is the process of finding errors or bugs. It asks: "Does the system work as intended?"

Debugging is the process of fixing errors. It involves locating the root cause and resolving it.

The Cycle:

Testing uncovers the flaw → Debugging removes it → Testing verifies the fix.

Testing Levels

Unit Testing

Testing the smallest possible components (a single function or method). Uses test drivers to execute code. Ensures individual logic units work before assembly.

Integration Testing

Tests interactions between modules, databases, and APIs. Focuses on the "integrated" system rather than isolated parts.

System Testing

The entire system is tested as a whole against functional requirements. Verifies end-to-end business processes.

Functional vs. Non-Functional

Category Definition Examples
Functional "What the system DOES" Login, Calculations, Data retrieval, API calls
Non-Functional "How the system PERFORMS" Speed, Security, Scalability, Accessibility, Usability

Modern LCCS projects must address Accessibility (Non-functional requirement).

Testing Methodologies

Black Box Testing

Internal logic is hidden. The tester only sees inputs and outputs. Focused on user requirements and functionality, not code structure.

White Box Testing

Internal logic is visible. The tester examines code paths, loops, and conditions. Focused on structural integrity and coverage.

Release Phases

Alpha Testing

Conducted by the internal development team at the developer's site before release to outside users.

Beta Testing

Conducted by real users in their own environment. Helps find unexpected bugs in real-world conditions.

Case Study: The Therac-25

A catastrophic failure of software testing in a 1980s radiation therapy machine. A "race condition" in the code caused patients to receive 100x the intended radiation. The software was never tested in integration with the hardware safely. Outcome: Fatalities and severe injuries due to poor error handling and lack of physical safety overrides.

User Design

Mastering the interface between humans and machines

Accessibility

Ensuring everyone can use the software, regardless of ability or disability.

Efficiency

Reducing the time taken to complete tasks through intuitive design.

User Satisfaction

Creating a positive emotional response and enjoyable experience.

The User Interface (UI)

The visual part of a system that a person interacts with. Includes buttons, icons, and menus.

GUI

Graphical User Interface — Windows, icons, mouse pointers. Visual and intuitive for general users.

CLI

Command Line Interface — Text-based, fast for experts. Precise but has a steep learning curve.

VUI

Voice User Interface — Alexa, Siri, Voice search. Hands-free interaction.

NUI

Natural User Interface — Touch, gestures, eye-tracking. Most intuitive physical interaction.

UI vs. UX

UI is the bridge — Is it pretty? (Layout, color, fonts). UX is the feeling — Is it helpful? (Logic, flow, ease of use).

Real Example: Spotify's "Discover Weekly" is a UX win — it creates value by understanding user behavior, not just looking good.

7 Principles of Universal Design

1 Equitable Use

Useful to people with diverse abilities. Ex: Automatic doors for everyone.

2 Flexibility in Use

Accommodates wide range of preferences. Ex: Left and right-handed scissors.

3 Simple & Intuitive

Easy to understand regardless of experience. Ex: Apple iPhone interface.

4 Perceptible Info

Communicates info effectively via multi-senses. Ex: Tactile elevator buttons.

5 Tolerance for Error

Minimizes hazards and adverse consequences. Ex: "Undo" button or file recovery.

6 Low Physical Effort

Used efficiently and comfortably. Ex: Lever door handles.

7 Size and Space

Appropriate space provided for reach/manipulation. Ex: Wide subway turnstiles for wheelchairs.

Modelling & Simulation

Understanding abstraction and execution over time

What is a Model?

A simplified, abstract representation of reality. It focuses only on variables relevant to the problem, removes unnecessary complexity, and uses mathematical rules or logic. Acts as the "blueprint" of a system.

What is a Simulation?

The act of running the model. It shows how the system changes over time under specific conditions. Dynamic, not static. Predicts future outcomes and allows for "What If" testing.

The Difference

Modelling is the design phase (the set of rules, equations, and logic). Simulation is the action phase (the software processing those rules). Think of it as the Blueprint versus the Construction.

Why Do We Need Them?

Safety

Test dangerous scenarios like flight training or fire escapes without risking human lives.

Efficiency

Modelling a bridge or product digitally is far cheaper than building physical prototypes that might fail.

Insight

Observe systems too fast (explosions) or too slow (climate change) to watch in real time.

Agent-Based Modelling (ABM)

Bottom-Up Approach

Instead of global equations, we model individual entities called "Agents" and watch how their small interactions create massive system-wide behaviour. There is no "master controller" — each agent makes its own decisions based on local surroundings and fixed rules.

Autonomy

Agents act independently without central control.

Local Rules

They only react to what is near them in their immediate environment.

Interaction

They bump into, follow, or influence other agents around them.

Emergent Behaviour

In bird flocking, each bird follows three simple rules: separation, alignment, and cohesion. No leader is assigned, yet complex, beautiful flocking patterns emerge from these local interactions.

Real-World Uses

Disease

Simulating how viruses spread to test lockdown or vaccine impact.

Traffic

Optimising city lights to prevent "phantom traffic jams".

Environment

Predicting global warming effects on ice caps and sea levels.

Electronics for CS

Voltage, current, components, and digital signals

The Fundamentals

Voltage (V)

The electrical "push" that makes electrons move. Think of it as water pressure at the source. Measured in Volts (V).

Current (I)

The actual rate of flow of electrical charge past a point. Think volume of water per second. Measured in Amps (A).

Resistance (R)

The "hose size" restricting flow. Limits current to protect sensitive components. Measured in Ohms (Ω).

Ohm's Law

V = I × R

Voltage equals Current multiplied by Resistance. The fundamental equation of electronics.

Essential Components

Semiconductors

Materials like Silicon that can behave as an insulator or conductor depending on conditions. The essential "building block" of all modern computing.

Resistors

Limit the amount of current that can flow. Without them, sensitive parts (like your Micro:bit) would burn out from too much power.

Transistors

Microscopic electronic switches with no moving parts. Either ON or OFF. A modern CPU contains billions of these, enabling binary data processing (0s and 1s).

Integrated Circuits (ICs)

A single piece of semiconductor with millions of transistors, resistors, and capacitors built onto it. This is why smartphones are thousands of times more powerful than old room-sized computers.

Analogue vs. Digital Signals

Analogue

Continuous
Signal Type

Can represent any value within a range. Examples: Human voice, music from vinyl, temperature sensors. Highly prone to noise.

Digital

Discrete
Signal Type

Uses discrete values — either "On" (1) or "Off" (0). The native language of CPUs. Very resistant to noise.

Real-World Examples

Micro:bit

Buttons are Digital (Pressed/Not). The Light Sensor is Analogue (detects brightness levels).

Game Controllers

D-Pad buttons are Digital. Analog sticks measure degrees of movement — Analogue input converted to Digital for processing.

Internal Processing

Even though we input analogue movement, the console uses ICs to convert it to digital signals for the CPU.

Embedded Systems

Specialized computing built for dedicated functions

What is an Embedded System?

A specialized computer system designed to perform a dedicated function. Unlike a general-purpose PC, it is "embedded" as part of a larger mechanical or electrical system. They contain both hardware (microcontrollers) and software (firmware), continuously reading inputs from sensors and controlling outputs.

Why Are They Needed?

Efficiency

Consume very little power. Hardware is optimized perfectly for one specific task without wasted resources.

Reliability

Highly stable. A washing machine's embedded system rarely crashes because the software is simple, tested, and isolated.

Form Factor

Incredibly small and cheap to produce at scale, allowing "smart" technology in almost any physical object.

Core Characteristics

Single-Functioned

Designed to do one specific task repeatedly (e.g., a digital thermometer only reads and displays temperature).

Real-Time Operation

Many are "reactive" — they must respond to external events within strict time constraints (e.g., car airbags).

Tightly Constrained

Operate with limited memory (RAM/ROM) and processing power to keep manufacturing costs and energy consumption low.

The Hardware

The brain is usually a Microcontroller (MCU). Unlike a standard CPU, an MCU packages the processor, memory (RAM/ROM), and programmable input/output peripherals all onto a single integrated circuit chip.

The Software

The code is called firmware. It is written to non-volatile memory (like Flash or ROM) and is rarely updated by the end-user during the lifetime of the device.

Real-World Applications

Smartwatches

Dedicated health monitoring and notification systems.

Smart Thermostats

Climate control with sensor feedback loops.

Microwaves

Precise timing and power control for cooking.

Automotive: The Modern Car

A modern vehicle contains dozens of embedded systems known as Electronic Control Units (ECUs). These control everything from engine fuel injection to anti-lock braking systems (ABS) and climate control. They must meet strict safety standards, as failures can be catastrophic.

The Internet of Things (IoT)

Historically, embedded systems operated in isolation. Today, IoT involves adding network connectivity to these devices, allowing them to send and receive data globally. This enables "Smart Cities" (intelligent traffic lights), precision agriculture (soil sensors), and remote healthcare monitoring.

Python Functions

Mastering decomposition, reusability, and abstraction

The Power of Reusability
Decomposition
Breaking a complex problem into smaller, bite-sized chunks.
DRY Principle
"Don't Repeat Yourself." Write code once and call it whenever needed.
Abstraction
Hiding complex logic behind a simple, descriptive name.
Defining a Function

Use the def keyword followed by the function name and parentheses.

# Define a function def greet_user():     # Code block inside     print("Hello, LCCS!")

Key Rule: Everything inside the function must be indented (4 spaces).

Parameters vs. Arguments

Parameters

The placeholders defined in the function header. They act as variables inside the function.

def greet(name):  # 'name' is a parameter     print("Hello,", name)
Arguments

The actual data you pass to the function when you call it from the main program.

greet("Alex")  # "Alex" is the argument Hello, Alex
Multiple Arguments

Functions can accept multiple inputs. Order matters — arguments are matched to parameters in the order they are passed.

def calc_area(length, width):     return length * width # Call with two arguments print(calc_area(5, 10))  # Output: 50

Return vs. No Return

The return Statement

Sends a value back to where the function was called. Allows you to store the result in a variable for later use.

def add(a, b):     return a + b result = add(3, 4) print(result)  # Output: 7
Procedures (No Return)

Functions without a return statement often just print to the screen. In Python, if you don't specify a return, the function implicitly returns None.

def say_hello():     print("Hello!") # Returns None implicitly

print() vs. return

Feature print() return
Purpose Shows info to the human user Passes info back to the computer
Data Storage Cannot be saved to a variable Result can be saved in a variable
Exit Behavior Function continues execution Exits the function immediately
Exam Tip

Section C of the LCCS exam frequently asks you to complete function definitions or trace return values. Understanding scoping and return logic is the key to a H1 grade.
